# AIOps 2.0 V7.7 — Architecture Review

## Purpose
V7.7 is a reliability hardening release. It does not add another historical platform; it consolidates execution around the canonical Run, Temporal, Twin, Evidence, Policy, Integration and Command Center boundaries.

## Critical fixes
- Outbox claim now uses the configured `OUTBOX_WORKER_ID`; V7.7 could reference an undefined `worker_id`.
- Stale `SENDING` outbox leases older than 60 seconds are returned to `PENDING`.
- Run event sequence allocation locks the parent Run row, preventing concurrent `max(sequence)+1` collisions.
- RAG/Intelligence are included in runtime qualification.
- A migration runner is executed after stack startup; SQL remains idempotent for clean bootstrap and controlled upgrades.
- Python bytecode caches are excluded from the release.

## Invariants
1. Temporal is the only Run executor.
2. The Twin is authoritative for topology/state context.
3. Evidence is the provenance boundary.
4. Policy is fail-closed.
5. DEMO/REPLAY/STORY never mutate LIVE state.
6. Outbox delivery is at-least-once with idempotent receipts.
7. A stale lease can be reclaimed without manual database surgery.
