# STAR — contrôle anti-attestation frauduleuse des archives

Le plan de captures `demo/star_legacy_capture_gap_plan.py` accepte des rapports historiques d'intégrité Playwright, mais **ne doit pas transformer une valeur saisie dans un ancien rapport en preuve runtime**. L'entrée était auparavant suffisamment permissive pour accepter `runtime_authenticated=true` ou `business_state_verified=true` dans une entrée historique, tout en générant un plan de capture. Désormais, les affirmations positives `runtime_authenticated`, `business_state_verified` et `eligible_for_star_proof` sont refusées explicitement avec `ValueError`; les champs d'attestation doivent être booléens et l'application dans l'une des catégories historiques reconnues. Les correspondances SHA restent seulement des indices d'intégrité documentaire.

Les tests `tests/test_star_legacy_capture_gap_plan.py` vérifient les faux témoignages runtime, les types incohérents et les applications non reconnues. Aucune élévation d'autorisation, accès réseau, écriture GLPI/n8n/Grafana ou validation de remédiation n'est effectuée. Les vraies preuves nécessitent toujours le navigateur isolé, la vérification de l'identité événement/run et une session authentifiée.
