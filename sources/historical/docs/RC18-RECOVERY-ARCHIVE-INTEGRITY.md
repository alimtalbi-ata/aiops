# AIOps 2.0 RC1.8 — recovery archive integrity increment

**Date:** 2026-10-20. **Owner:** Abdelhalim Talbi. **PR:** #21.
**Last accepted baseline:** RC1.7 GitHub Actions #39408586135 (all jobs successful).

## Implemented
- Check every volume TAR member for normalized-path uniqueness before restore.
- Reject replay of a member path such as two entries of `./file.txt` with differing contents, even if the outer SHA-256 manifest is recomputed correctly.
- Permit conventional root-directory metadata `./` generated by volume backups, without relaxing restrictions on special members, links, path traversal or unsafe file types.
- Add automated positive and adversarial tests that run in the mandatory quality-build job.

## Unqualified boundaries
This hardening does not constitute the planned full-stack recovery rehearsal. No actual MariaDB, Temporal visibility or persistent volume full restore has been executed by this increment. No production server action, no LIVE remediation, no merge to main.
